# Обсидиан — лендинг веб-студии

Сайт без сборки: HTML, CSS и JavaScript, PHP-обработчик формы. GSAP, ScrollTrigger и Lucide подключаются через CDN; для их загрузки нужен доступ в интернет.

## Локальный запуск

Из папки сайта выполните:

```sh
php -S localhost:8000
```

Откройте http://localhost:8000. Можно также открыть `index.html` напрямую в браузере, но локальный HTTP-сервер предпочтительнее для проверки запросов и поведения сайта: при открытии через `file://` ограничения браузера и CORS могут отличаться.

## Публикация

Разместите содержимое папки сайта на хостинге с PHP, настроив `index.html` как главную страницу. Сохраняйте структуру каталогов и относительные пути. В production настройте HTTPS, проверьте доступность файлов, CDN, значка сайта и формы на опубликованном домене.

Пример политики кэширования на хостинге:

- HTML: `Cache-Control: no-cache` — браузер проверяет актуальность перед повторным использованием.
- Статические CSS, JS, изображения, шрифты и иконки со стабильными именами: `Cache-Control: public, max-age=3600`. Обновления таких файлов могут быть незаметны до истечения часа; для долгого кэширования используйте версионированные имена или URL и только тогда увеличивайте срок.

## Форма и API

Кнопки обсуждения открывают форму во всплывающем окне; на страницах кейсов форма загружается с главной страницы. Если загрузить её не удалось, окно предложит перейти на главную. Без JavaScript форма остаётся в разделе контактов, но отправка недоступна. Форма отправляет JSON-запрос в `send-project.php`. Обработчик проверяет поля и согласие, затем передаёт одно письмо получателям `ceo@obsidianweb.ru` и `vn210494@ya.ru` от `notify@obsiweb.ru` через PHP `mail()`. Ошибка передачи показывается посетителю, данные остаются в форме. При успешной передаче форма очищается; это подтверждает приём сервером почты, но не доставку в почтовые ящики.

На хостинге нужны PHP с включённой функцией `mail()` и настроенный почтовый транспорт, который разрешает отправку с `notify@obsiweb.ru` (включая envelope sender). Настройте для домена `obsiweb.ru` SPF и DKIM согласно требованиям почтового провайдера. Проверьте доставку в оба ящика, включая папку «Спам», и журнал почтового сервера. Если хостинг предоставляет только SMTP с авторизацией, необходима отдельная SMTP-интеграция; пароли нельзя размещать в коде или в публичной папке. Обеспечьте защиту от спама и ограничение частоты запросов на хостинге, а также безопасную обработку персональных данных.

## Перед запуском

- Добавьте юридические реквизиты; проверьте актуальность контактов, услуг и цен или условий расчёта стоимости.
- Подготовьте и опубликуйте политику обработки персональных данных, настройте ссылку и текст согласия в форме в соответствии с применимыми требованиями.
- Замените примеры отзывов в `index.html` подтверждёнными отзывами с разрешением на публикацию. Добавляйте только реальные проекты портфолио с разрешением на публикацию; не выдавайте демонстрационные макеты за клиентские кейсы.
- `https://example.com/` в canonical, Open Graph, структурированных данных, `sitemap.xml` и `robots.txt` — **заглушка, не домен сайта**. Перед публикацией замените её на реальный публичный HTTPS-домен во всех этих местах. Размещайте sitemap и robots в корне домена и проверьте их доступность и согласованность адресов.
- Проверьте структурированные данные schema.org и добавляйте только достоверные сведения об организации.
- Проверьте доставку формы, HTTPS, защиту от спама и обработку персональных данных; при необходимости отдельно подключите CRM.

## Портфолио

Девять карточек и отдельных страниц кейсов размещены непосредственно в HTML и доступны без JavaScript. После двух избранных проектов показана горизонтальная лента из семи карточек: её можно прокручивать, а при включённом JavaScript — также листать стрелками. Страницы новых кейсов используют локальные снимки главной и внутренней страниц сайтов. Для «Юник С» платформа не указана, поскольку она не подтверждена. До публикации согласуйте с клиентами размещение кейсов и скриншотов, проверьте актуальность ссылок и подтверждение участия студии в каждом проекте.

Дополнительные реальные проекты с разрешением на публикацию можно добавить в массив `projects` в `js/portfolio.js`: они дополняют статические карточки, не заменяя их и описание раздела. Эти дополнительные карточки отображаются при включённом JavaScript; для доступности без JavaScript добавляйте их непосредственно в HTML. Поля массива: `title`, `description`, `category`, `sphere`, `image` (путь или URL изображения), `imageAlt` (осмысленное описание изображения) и `url` (ссылка на проект). Относительные пути задаются относительно главной страницы. Рекомендуемый размер изображения — 1200 × 900 пикселей. Если ссылки или изображения нет, соответствующий элемент скрывается. При добавлении отдельной страницы обновите `sitemap.xml`, canonical и Open Graph.

## Структура

- `index.html` — страница сайта.
- `send-project.php` — обработчик заявок и отправка уведомлений.
- `cases/lesnoe.html` — отдельная страница проекта «Лесное».
- `cases/komz40.html` — отдельная страница проекта Калужского опытно-механического завода.
- `cases/a-clinic.html`, `cases/estetica.html`, `cases/instom.html` — страницы стоматологических клиник.
- `cases/ideastroy.html`, `cases/congear.html`, `cases/uniqset.html`, `cases/diaconia.html` — страницы компании по ремонту, производства шестерён, поставщика оборудования и благотворительного фонда.
- `css/` — стили; `js/` — поведение страницы и отправка формы.
- `assets/images/`, `assets/fonts/`, `assets/icons/` — каталоги для локальных ресурсов.
- `favicon.svg` — авторский геометрический знак для вкладки браузера.
- `robots.txt`, `sitemap.xml` — файлы для поисковых роботов; до запуска содержат домен-заглушку.
